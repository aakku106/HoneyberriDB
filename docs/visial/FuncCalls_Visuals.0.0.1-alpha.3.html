non-negotiables

Rules the call graph keeps

⇄

Lock order

db.mu → wal.mu. Never the reverse. OpenDb scans while holding the DB lock; Set wraps both locks.

↓

Write order

newRecord → appendRecord + fsync → applyLocked → lastSeq. Disk first, memory second.

◫

Snapshot order

temp file → write → fsync → close → rename → syncDir. snapMu keeps writers from sharing the temp path.

⌁

Failure policy

Bad WAL lines are counted and skipped. A bad snapshot is ignored and the full WAL is replayed. Neither is fatal.
